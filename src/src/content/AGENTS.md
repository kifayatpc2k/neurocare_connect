## Content rules
- Study Team page text lives only in `src/content/study-team.ts`; the `/study-team` route just renders it, so non-developers can update people and credits in one file; its hero is a separate hand-rolled canvas (`StudyTeamResearchNetwork.tsx`). Text in [brackets] renders as a visible "pending" placeholder.
- Homepage wording lives only in `src/content/home.ts`; the hero neural visual is a hand-rolled SVG projection (`src/components/home/NeuralScene.tsx`), not a 3D library, to keep the page light and SSR-safe.
- Study page text lives only in `src/content/study.ts`; the `/study` route renders it and components consume it (no hardcoded copy in components). The hero visual is a hand-rolled 3D nerve-fibre network projected onto a canvas (`src/components/study/StudyHeroVisual.tsx`) — no 3D library, colours read from theme tokens, reduced-motion safe.
- Education library text lives only in `src/content/patient/library.ts` (rendered under `/patient/library`); articles stay `awaiting-review` with real sources until a clinician signs off.

- The patient area (`/patient`) is public with no patient accounts; its text lives only in `src/content/patient/*` and Ask NeuroCare is a deterministic local matcher (`src/lib/education/answer-engine.ts`: emergency rules → treatment-decline rules → exact question → medicine names → synonyms in `synonyms.ts` → ranked search over `content-index.ts`, which is derived from the existing content sources, linking only to `Target` patient routes) — no AI service, no network, nothing stored — so patients never see unapproved or personalised guidance. Old patient sign-in URLs redirect to `/patient`.
